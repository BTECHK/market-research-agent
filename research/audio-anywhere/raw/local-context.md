# Local (Platform) Context — Audio Anywhere

*Adapted from the Local Context template: "geography" = iOS-first, US-first. Research date: 2026-09-25. Depth: deep dive, adversarial.*

**Bottom line:** MVP1 (Google Docs + PDF → long-form listening with saved progress) is technically straightforward on iOS. The founder's long-term vision ("read anything from anywhere on your phone", including texts) is **not achievable on iOS** as a passive, system-level reader. The ceiling is "anything the user *pushes* to the app" via the Share Sheet, a Safari extension, screenshot/OCR, copy-paste and Shortcuts. Incumbents already ship every one of those paths, so "read from anywhere" gives no edge on iOS. The real technical edge is in **document cleanup** (PDF reading order, headers/footers, footnotes) and **long-session reliability**.

## 1. iOS technical feasibility & constraints

| Capability | Feasible? | Notes / implication |
|---|---|---|
| Read other apps' content directly | **No** | Every third-party iOS app runs in a sandbox. Apps "access information other than [their] own only by using services explicitly provided by iOS" ([Apple Platform Security](https://support.apple.com/guide/security/security-of-runtime-process-sec15bfe098e/web)). |
| Read iMessage/SMS texts | **No (confirmed)** | No public API exposes the Messages database. iMessage *app extensions* can only add stickers or apps inside a conversation. They cannot read the message history ([AppleInsider on iOS 10 Messages extensions](https://appleinsider.com/articles/16/06/14/inside-ios-10-third-party-compatibility-opens-up-messages-to-apples-app-universe)). The only route is the user copying text or taking a screenshot and passing it to the app. |
| Android-style Accessibility reading | iOS **No** / Android **Yes** | Android's `AccessibilityService` can inspect other apps' UI and text across apps. It is powerful but a well-known malware vector and is policed by Google Play ([Android docs](https://developer.android.com/reference/android/accessibilityservice/AccessibilityService), [Guardsquare](https://www.guardsquare.com/mobile-app-security-research-center/malware/accessibility-service-malware)). iOS has no equivalent for third parties. VoiceOver and Speak Screen are OS-only. **So the "anywhere" vision is really an Android feature.** |
| Share Sheet / Share Extension | Yes | This is the main "from anywhere" path. It takes URLs, PDFs, text and files from Safari, Mail, Files, Google Docs (via "Send a copy") and similar apps. Speechify and ElevenReader both use it ([Speechify](https://speechify.com/blog/listen-to-a-webpage/), [ElevenLabs help](https://help.elevenlabs.io/hc/en-us/articles/26197616307985-How-do-I-add-content-to-ElevenReader)). |
| Action extension | Yes | Works like the Share Sheet, but can act in place, for example "Listen now". |
| Safari Web Extension (iOS) | Yes | Speechify ships one that reads any website ([Speechify](https://speechify.com/blog/listen-to-websites-with-the-safari-extension-on-ios/)). |
| Screenshot / camera OCR | Yes | This is the fallback for texts, other apps and paper. Speechify and ElevenReader both offer scan/photo-to-audio ([Speechify App Store](https://apps.apple.com/fm/app/speechify-audio-text-reader/id1209815023), [ElevenReader](https://elevenreader.io/text-reader-app)). Vision `RecognizeDocumentsRequest` (iOS 26) returns paragraphs, lists and tables ([WWDC25](https://developer.apple.com/videos/play/wwdc2025/272/)). |
| App Intents / Shortcuts / Siri | Yes | `AudioPlaybackIntent` lets Siri, Shortcuts and widgets start playback ([Apple docs](https://developer.apple.com/documentation/appintents/audioplaybackintent)). A Shortcut can grab the clipboard or a screenshot and send it to the app, which is the closest thing to "read anything" on iOS. |
| Files / File Provider | Yes | The app can import from the Files app and from cloud providers, including Google Drive through the Files app. |
| Background audio + lock screen | Yes | Requires the `playback` audio session category, the background audio mode, `MPNowPlayingInfoCenter` and `MPRemoteCommandCenter` ([Apple AVAudioSession](https://developer.apple.com/documentation/AVFAudio/AVAudioSession)). On-device `AVSpeechSynthesizer` has known background and interruption quirks ([dev forum](https://developer.apple.com/forums/thread/27097), [iOS 16.5 bg bug](https://developer.apple.com/forums/thread/732576)). Pre-rendering cloud TTS to audio files avoids them and is how you get "audiobook-grade" playback. |
| Live Activities | Yes | Useful for showing progress ("Chapter 3 · 42%") on the Lock Screen and Dynamic Island. Nice to have, not a moat. |
| CarPlay | **Ambiguous / gated** | Requires an audio-app entitlement that Apple approves ([Apple](https://developer.apple.com/documentation/carplay/requesting-carplay-entitlements)). Search excerpts of the CarPlay Developer Guide say audio apps must not use "text-to-speech systems" ([guide PDF](https://developer.apple.com/download/files/CarPlay-Developer-Guide.pdf)). Yet Instapaper ([blog](https://blog.instapaper.com/post/716397810350784513)) and Speech Central ([post](https://speechcentral.net/2024/05/08/nhance-your-carplay-experience-with-speech-centrals-text-to-speech-for-documents/)) ship TTS article/document playback in CarPlay. iOS 26.4 added a separate voice-conversational CarPlay category ([AppleInsider](https://appleinsider.com/articles/26/02/18/ai-agents-are-coming-to-carplay-but-theyre-not-getting-the-keys)). **Risk:** approval is uncertain. Pre-rendered audio files likely fit "audio app" better than live TTS. |

**Built-in TTS pain is real (supports H1):** Apple Community and AppleVis users report that Speak Screen stops midway, jumps back to the top, skips words while auto-scrolling, and stops at chapter ends ([thread 1](https://discussions.apple.com/thread/255296525), [thread 2](https://discussions.apple.com/thread/254397861), [iOS 26](https://discussions.apple.com/thread/256137942), [AppleVis](https://www.applevis.com/forum/ios-ipados/apple-books-speak-screen)).

## 2. Google Docs integration

- **Restricted scopes** (`drive`, `drive.readonly`) require restricted-scope verification plus a **CASA** security assessment by an approved lab, **repeated every 12 months** ([Google](https://developers.google.com/identity/protocols/oauth2/production-readiness/restricted-scope-verification), [Security Assessment help](https://support.google.com/cloud/answer/13465431?hl=en)). The cost is roughly $500–$4,500 or more per year depending on tier. Google has negotiated a discounted Tier 2 rate with TAC Security ([DeepStrike](https://deepstrike.io/blog/google-casa-security-assessment-2025), [Agentic Fabriq](https://www.agenticfabriq.com/blog/google-oauth-verification-casa)). Expect weeks of calendar time.
- **Workaround:** use the `drive.file` scope with the **Google Picker**. This scope is **non-sensitive**: no CASA, only basic verification, and the app gets per-file access only to files the user picks ([Google scopes guide](https://developers.google.com/workspace/drive/api/guides/api-specific-auth), [GitHub discussion](https://github.com/CarlosCamacho/Drive-Dupe-Destroyer/issues/28)). The trade-off is that you cannot browse or sync the user's whole Drive, and you must use Google's picker UI, which is awkward on native iOS. **Recommendation for MVP1: `drive.file` + Picker, plus the Share Sheet from the Google Docs app. Avoid restricted scopes until revenue justifies CASA.**
- **Export:** `files.export` supports `text/plain`, `text/markdown`, HTML (as a zip), docx, EPUB and PDF, with a **10 MB export cap** that returns `exportSizeLimitExceeded` ([files.export](https://developers.google.com/workspace/drive/api/reference/rest/v3/files/export), [MIME types](https://developers.google.com/workspace/drive/api/guides/ref-export-formats), [issue tracker](https://issuetracker.google.com/issues/308836075)). Markdown or HTML keeps headings, which helps chapter navigation. The Docs API gives structured JSON, including footnotes, if needed.
- **Competitor parity:** Speechify already links Google Drive on iOS and the web ([Speechify](https://speechify.com/blog/link-google-drive-to-speechify-ios-app/)). Google Docs import is table stakes, not a differentiator.

## 3. PDF parsing quality for TTS (the real wedge)

- **Known failure modes:** TTS reads headers, footers, page numbers and margin text, often in the middle of a sentence where a sentence crosses a page break. Footnotes are not separated from body text. Multi-column layouts get the wrong reading order, and tables come out as garbled text ([Nick Byrd](https://byrdnick.com/archives/11077/pdf-footnotes-accessibility-of-research), [Hampshire College K3000 guide](https://resourceguides.hampshire.edu/k3000/accessiblePDF), [header/footer avoidance patent](https://patents.google.com/patent/US6256610)). Few consumer apps skip headers and footers; the Voyzer/vBookz family does ([PDFSpeech guide](https://www.onekerato.com/pdfspeech-user-guide.html)).
- **Solutions:**
  - **PDFKit** handles text extraction but gives no semantic structure.
  - **Vision `RecognizeDocumentsRequest`** (iOS 26) runs on-device and returns paragraphs, tables and lists ([docs](https://developer.apple.com/documentation/vision/recognizedocumentsrequest)).
  - **Cloud parsers:** Mistral OCR 3 costs about $1–2 per 1,000 pages and labels regions as header, footer, aside or reference in reading order. Multi-column academic papers can still scramble ([Mistral](https://mistral.ai/news/mistral-ocr-3/), [PyImageSearch](https://pyimagesearch.com/2025/12/23/mistral-ocr-3-technical-review-sota-document-parsing-at-commodity-pricing/)). LlamaParse costs about $3.75 per 1,000 pages ([comparocrapi](https://comparocrapi.online/)).
  - **LLM cleanup pass:** removes boilerplate, turns tables into prose and moves footnotes to the end of a section. This is cheap relative to TTS cost.
- **Implication:** at about $0.002 per page, parsing cost is negligible. The quality of *cleanup* is a defensible, demo-able differentiator for the "20-page briefing" use case. Any document sent to a cloud LLM or TTS provider triggers Apple's Guideline 5.1.2(i) disclosure (see §4).

## 4. App Store rules

- **US anti-steering:** On 2025-04-30 the court in *Epic v. Apple* banned commissions on link-outs and scare screens ([Wikipedia](https://en.wikipedia.org/wiki/Epic_Games_v._Apple), [RevenueCat](https://www.revenuecat.com/blog/growth/apple-anti-steering-ruling-monetization-strategy)). Apple updated guidelines 3.1.1(a) and 3.1.3 for the US storefront on 2025-05-01, and no entitlement is needed ([9to5Mac](https://9to5mac.com/2025/05/01/apple-app-store-guidelines-external-links/), [Guidelines](https://developer.apple.com/app-store/review/guidelines/)). **Caveat:** on 2025-12-11 the Ninth Circuit ruled that Apple may charge a "reasonable" commission on linked purchases. The amount is still being set ([MacRumors](https://www.macrumors.com/2025/12/11/apple-app-store-fees-external-payment-links/), [Justia](https://law.justia.com/cases/federal/appellate-courts/ca9/25-2935/25-2935-2025-12-11.html)). Do not build a model that depends on a 0% web-checkout fee lasting.
- **Small Business Program:** 15% commission when proceeds are under $1M in the prior year. On the standard tier, subscriptions also drop to 15% after one year ([Apple](https://developer.apple.com/app-store/small-business-program/), [RevenueCat](https://www.revenuecat.com/blog/engineering/small-business-program)). **Implication:** at small scale, in-app purchase at 15% versus web checkout at about 3% plus some Apple fee is a modest gap. Test both.
- **AI rules:** Guideline 5.1.2(i) (2025-11-13) requires telling users which third-party AI (LLM, TTS or ML) receives their personal data, and getting explicit consent first. Apps have been rejected under it ([TechCrunch](https://techcrunch.com/2025/11/13/apples-new-app-review-guidelines-clamp-down-on-apps-sharing-personal-data-with-third-party-ai), [Apple news](https://developer.apple.com/news/?id=ey6d8onl), [dev forum rejection](https://developer.apple.com/forums/thread/816140)). Uploaded documents count as personal data, so an onboarding consent screen is needed. Voice cloning and impersonation fall under the general IP and impersonation rules. Avoid celebrity voices.
- **ASO:** Speechify dominates "text to speech", with 50M+ users claimed and 500K+ five-star ratings ([Speechify](https://speechify.com/)). ElevenReader, NaturalReader and Voice Dream follow. The head keyword is effectively unwinnable. Target long-tail terms such as "read PDF aloud", "Google Docs reader", "listen to documents", "dyslexia reader" and "briefing reader". I found no hard keyword-volume data; this needs AppTweak or Sensor Tower.

## 5. Desktop

- **Competitors:** Speechify has a Chrome extension, a native Mac app and a web app ([Speechify download](https://speechify.com/download/), [Mac](https://speechify.com/mac/)). ElevenReader has a browser extension plus iOS and Android apps ([ElevenReader Chrome](https://elevenreader.io/text-to-speech-chrome-extension)). Voice Dream rebuilt its Mac app natively instead of using Catalyst ([Voice Dream](https://www.voicedream.com/introducing-macos-reader/), [AFB review](https://afb.org/aw/23/7/17989)).
- **Path:** Mac Catalyst or "Designed for iPad on Apple Silicon" is nearly free for a Mac v1. A **Chrome extension** is the higher-leverage desktop surface, because it reaches Google Docs directly in the browser, works on Windows and Chromebooks (important for schools), and avoids OAuth scopes for docs the user has open.

## 6. Accessibility-market channels

- **US state Vocational Rehabilitation:** these federally funded, state-run agencies fund assistive technology, including TTS and OCR readers, for employment and college ([ATIA funding guide](https://www.atia.org/home/at-resources/what-is-at/resources-funding-guide/), [NE Low Vision](https://nelowvision.com/vocational-rehabilitation-assistive-technology/), [JAN](https://askjan.org/topics/tech.cfm)). Purchases go through counselors and vendors, which requires perpetual or annual licenses and invoicing, not only App Store subscriptions.
- **University disability services:** these offices standardize on site licenses such as Read&Write, OrbitNote and Immersive Reader ([Virginia Tech SSD](https://ssd.vt.edu/access/assistive_tech.html)). Procurement requires a **VPAT/ACR** ([Section508.gov](https://www.section508.gov/sell/acr-vpat-faq/), [Level Access](https://www.levelaccess.com/blog/vpats-and-acrs-what-you-need-to-know/)). The ADA Title II WCAG 2.1 AA deadlines were extended to April 2027 and April 2028, so public universities are tightening software accessibility reviews ([McGraw Hill](https://www.mheducation.com/highered/blog/2026/03/how-to-read-and-interpret-an-acr-or-vpat-a-guide-for-higher-education-professionals.html)).
- **UK DSA:** incumbents are ClaroRead, with 86K+ licences through DSA and Access to Work, and Texthelp ([Claro](https://www.clarosoftware.com/education/disabled-students-allowance/), [Texthelp](https://www.texthelp.com/en-gb/solutions/dsa/)). **Headwind:** a DfE consultation opened on 2026-03-26 proposes funding assistive software only where free OS-built-in tools fall short. The response is due in autumn 2026 ([DfE consultation](https://consult.education.gov.uk/disabled-students-allowance-team/assistive-software-funded-through-disabled-student), [Computer Weekly](https://www.computerweekly.com/news/366643997/DfE-proposes-changes-to-student-funding-for-assistive-technology), [Education Business](https://educationbusinessuk.net/news/02062026/calls-stop-funding-cuts-assistive-technology)). This signals that governments view built-in TTS as "good enough", which is the opposite of H1 and a positioning risk for accessibility sales.
- **PM signal:** AppleVis is a dense, vocal community of blind and low-vision iOS users who review TTS readers in detail ([AppleVis ElevenReader](https://www.applevis.com/apps/ios/utilities/elevenreader-read-text-aloud)). It is a good early-feedback channel.

## Execution Recommendations

1. **Scope:** Drop "texts/iMessage" from the iOS roadmap because it is technically impossible. Reframe "anywhere" as Share Sheet, Safari extension, screenshot/OCR and a Shortcut, all of which are parity features. Put Android on the roadmap if system-wide reading matters.
2. **Differentiate on document intelligence and long-session reliability:** header/footer/footnote stripping, correct reading order, table narration, and resume-exactly-where-you-left-off across devices. These are the documented failure points of incumbents and built-in tools.
3. **Google:** ship with `drive.file` + Picker plus the Share Sheet. Defer restricted scopes and CASA.
4. **Audio architecture:** pre-render cloud TTS to audio files. This gives reliable background playback, lock-screen controls, offline listening and a cleaner case for CarPlay approval.
5. **Payments:** use in-app purchase at 15% through the Small Business Program, plus a US web-checkout link to test. Do not assume the web fee stays at 0%.
6. **Compliance:** add a 5.1.2(i) AI-disclosure consent screen at onboarding, and a VPAT before any B2B or education sales.
7. **Desktop:** build a Chrome extension before a native Mac app.
